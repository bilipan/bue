# bue

本地 Markdown 预览服务器。`bue 某个.md` 直接起服务并在浏览器里渲染，支持 Mermaid、代码高亮、表格和目录导航。

```bash
bue README.md
```

## 安装

需要 Node 22.18 以上（用到 Node 原生的 TypeScript 执行，无构建步骤）。

```bash
pnpm install
pnpm link --global     # 得到全局 bue 命令
```

## 用法

```bash
bue <file|dir...> [选项]
```

| 选项 | 说明 |
| --- | --- |
| `-p, --port <n>` | 监听端口，默认从 3000 起自动探测空闲端口 |
| `-H, --host <host>` | 监听地址，默认 `127.0.0.1` |
| `-t, --theme <mode>` | `auto`（默认，跟随系统）/ `light` / `dark` |
| `--width <px>` | 正文宽度，默认 `768` |
| `--no-toc` | 隐藏右侧目录。正文随之居中并放宽到原本预留给目录的宽度 |
| `--no-open` | 启动后不自动打开浏览器 |
| `-v, --version` `-h, --help` | 版本号 / 帮助 |

```bash
bue README.md                  # 单文件
bue docs/                       # 整个目录，递归扫描并生成站内导航
bue a.md b.md                   # 多个文件
bue docs/ --no-open --port 4000  # 不自动开浏览器，指定端口
```

## 刷新方式

**每次请求都会重新读盘并渲染**，所以改完文件按 `Cmd+R` / `F5` 即可看到最新内容。

本工具**不做文件监听、不做自动热重载**——这是刻意的取舍：省掉 watcher 和 SSE 长连接，换来更少的活动部件。按一下刷新键的成本远小于维护长连接的复杂度。

## 支持的能力

- **Markdown**：marked + GFM，表格、任务列表、脚注式引用
- **Mermaid**：` ```mermaid ` 代码块，浏览器端渲染。渲染失败时在该位置显示错误和源码，不会白屏。节点不带投影（mermaid 自带的阴影已关掉）
- **图缩放**：每张图右上角浮着四个图标按钮 —— 拖动模式、缩小、放大、适配容器尺寸。**缩放不改变图框尺寸**，只是把内容放大到框内查看；拖动模式一打开就能按住图上下左右拖动画布，不要求当前是不是在适配尺寸。切主题重绘后缩放保持不变
- **代码高亮**：highlight.js，内联复制按钮
- **相对资源**：md 里的 `./img/a.png`、指向其他 md 的 `[链接](guide/install.md)` 都会被改写成站内路由，目录模式可以直接互跳
- **文档间跳转**：跨文档链接按盘上真实路径解析，**不依赖启动时的扫描清单**——`bue a.md` 里链到隔壁的 `b.md` 照样打得开；链到目录则落到该目录的 README
- **目录**：右侧折叠面板，`IntersectionObserver` 滚动高亮，宽屏常驻 / 窄屏抽屉。隐藏时（`--no-toc` 或文档没有标题）正文居中，并吃下原本预留给目录的宽度
- **主题**：CSS `light-dark()` 双主题，跟随系统，可手动切换并记住选择
- **中文标题锚点**：`## 安装` → `#安装`，重名标题自动加 `-2` 后缀

## 路由

| 路由 | 说明 |
| --- | --- |
| `/` | 单文件渲染该文件；目录模式渲染 `README.md`，没有则给文件索引页 |
| `/d/<slug>` | 打开某篇文档，slug 为相对路径去扩展名 |
| `/p/<path>` | 按盘上路径打开文档（含扩展名）。用于没被扫描进清单的文档，比如单文件模式里链到的兄弟文件 |
| `/raw/<slug>` | 查看 Markdown 源码 |
| `/assets/*` | 文档根目录下的静态资源（图片、pdf…） |
| `/vendor/mermaid.js` `/vendor/hljs/*.css` | 前端依赖 |

## 设计取舍

几个刻意的决定，记录下来免得以后「优化」掉：

- **HTML 一律 `no-store`，前端资源走长缓存。** 每次请求都重新渲染，所以绝不能让浏览器拿旧副本；mermaid 有 5.5MB，重复预览时不该反复重传。
- **mermaid 用 UMD 单文件而不是 ESM 入口。** `mermaid.esm.min.js` 是 30KB 的懒加载入口，一个 `flowchart-elk` 就要拉 1.6MB 的 elk chunk。UMD 版本全量内联，没有 chunk 瀑布。
- **正文宽度上限写在 CSS，不是内联 style。** 内联的 `max-width` 优先级高于任何类规则，会把「没有目录时放宽」这条压掉。同理 `has-toc` 只在真的渲染出目录时才加，避免为一个空侧栏预留 320px。
- **mermaid 的节点投影要去两处才干净。** 主题变量 `dropShadow` 管它注入在 svg 内部 `<style>` 里的那些；sequence 的 actor 是把 `filter="url(#…-drop-shadow)"` 直接写成属性的，主题变量管不到，得靠 CSS 压（呈现属性本来就输给作者样式，不必上 `!important`）。
- **图的缩放值存在 `figure[data-zoom]` 上，不存在 svg 或 `.mermaid` 里。** 主题切换会重绘并清空 `.mermaid`，缩放值得活在重绘之外才留得住；重绘完再把新 svg 套回同一个值。
- **`data-zoom` 记的是「相对适配容器的倍数」，不是绝对像素。** 1 = 刚好铺满列宽（即加缩放之前的原样），2 = 两倍宽。记绝对像素的话列宽一变就得逐图重算；记倍数则只需重套一遍，容器的变化由 `fitRatio()` 吸收。
- **适配（倍数 1）时不动 svg 的内联样式。** mermaid 自己写的 `max-width` 就是图的固有宽度：窄图不放大、宽图由 CSS 收窄。清成空串会让 svg 退回 `width="100%"` 撑满容器，把小图拉变形。放大时才反过来显式写 `max-width: none` + 固定 px 宽。
- **缩放不改外框尺寸。** viewport 的高度在 JS 里按「适配时的图高」写死，缩放只改内部可视范围 —— 否则放大一张竖长的图会把图框一起顶高、整页跟着跳。图框因此是一个固定大小的取景窗，两个方向都能平移。
- **缩放以视口中心为锚。** 不锚定的话每点一次放大都在往右跳，配合拖动根本没法盯住某一块。
- **两轴都要能滚，`safe center` 也要两轴都给。** 竖长的图放大后往往只溢出纵向，只给横向滚动那半截就永远看不到。配套两个别改的细节：viewport 是 `box-sizing: content-box`（否则内边距从锁高里扣，适配时凭空多出纵向溢出），svg 是 `display: block`（inline svg 底下留约 7px 基线间隙，同样会变成一条多余的滚动条）。
- **平移有两条路，择一而用。** 内容比框大就用 viewport 的滚动（和滚动条、滚轮天然一致）；内容比框小时滚动根本没有范围，改用 `transform` 在空出来的空隙里挪 —— 这正是「适配尺寸」或「缩小到比框还小」时也该能拖画布的原因。同一轴上两条不能同时生效，否则会互相打架。
- **拖动模式一开就接管手势，不看是不是适配尺寸。** 拖动模式的意义就是拖画布，等用户先放大到溢出才生效是反的。只有真的「无处可挪」（宽图刚好铺满框）时才放行，否则 `preventDefault` / `touch-action: none` 会把窄屏上的页面滚动吃掉 —— 页面滚动什么时候都得留着。
- **拖动模式只在「开着 + 真的横向溢出」时才接管手势。** 否则 `preventDefault()` 和 `touch-action: none` 会把选中文本和窄屏上的页面滚动一起吃掉 —— 页面滚动什么时候都得留着，和目录抽屉、图片灯箱一个原则。
- **工具条浮在图上，不占文档流。** `position: absolute` 贴在 figure 右上角，图多高都不顶布局；因此 `.mermaid-figure` 得是 `position: relative`。
- **每次渲染都新建 `Marked` 实例。** 渲染器闭包里持有本次的标题 id 映射，复用实例会让并发请求互相污染。
- **标题 id 在渲染时分配，不靠预扫描源码。** marked 还认 setext 标题（`===` 下划线式），预扫描的正则会漏算导致 id 整体错位。
- **路径安全边界是工作区根目录，不是当前文档目录。** `../README.md` 在工作区内是合法的，拿文档目录当边界会把站内相对链接全判成越界。
- **扫描清单只管导航，不管「这篇能不能打开」。** workspace 是启动时扫出来的，单文件模式只有一篇；文档里链到的文件哪怕不在清单里，只要在工作区根目录内、且确实是 markdown，就应该打得开（走 `/p/<path>`）。曾经在这里返回原始相对 href，浏览器拿它对着 `/d/<slug>` 一解析就必然 404。
- **`.md` 链接有 `/d/` 和 `/p/` 两个地址，别只认一个。** 在清单里的用 `/d/<slug>`（短、稳定、进索引）；不在的用 `/p/<路径>`。`/p/` 命中清单同 slug 时 302 归一到 `/d/`，避免一篇文档两个地址。
- **链到目录落到该目录的 README。** 没有 README 就保持原样——目录本身不是文档，bue 不给目录做列表页。
- **不做 HTML 消毒。** 它只预览你自己的本地文件，引入 DOMPurify 只会增加摩擦。

## 已知限制

- 没有自动热重载，按 `Cmd+R` 刷新。
- 目录模式递归深度上限 12 层，自动跳过 `node_modules`、`.git`、`dist`、点目录。
- `[进目录](some/dir)` 需要该目录里有 README 才会跳转；没有的话链接保持原样，点进去是 404。
- Mermaid 需要 WASM 的图类型（`flowchart-elk`、handDrawn 风格）在个别环境下可能失败，会回落到显示源码。
- 忘了关进程会占住端口：`pkill bue`。

## 开发

```bash
pnpm test        # node --test
pnpm typecheck   # tsc --noEmit
pnpm start -- examples/demo.md
```

`examples/demo.md` 是覆盖全部能力的验收样例，`examples/docs/` 是多文件目录模式样例。
